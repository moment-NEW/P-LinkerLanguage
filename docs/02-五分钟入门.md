# 五分钟入门

本章从当前仓库的 demo 开始。完成后会得到：一个初始化表、一个从 Flash 复制到 RAM 的函数区，以及一段固定保留 RAM。

## 1. 前置条件

- Python 3。
- GNU Arm 工具链或 Arm Compiler 6。
- 任意 Cortex-M 项目，或本仓库的示例文件。

本机已验证的工具链记录在用户环境中；项目本身不强制要求特定版本。

## 2. 写布局文件

复制 [example/layout.pl.c](../example/layout.pl.c) 到你的工程。其核心结构如下：

```c
#include "pl_linker_layout.h"

const pl_memory_t pl_memories[] = {
    {
        .name = "FLASH",
        .origin = 0x08000000,
        .size = PL_KIB(512),
        .attributes = PL_MEMORY_RX,
    },
    {
        .name = "RAM",
        .origin = 0x20000000,
        .size = PL_KIB(128),
        .attributes = PL_MEMORY_RWX,
    },
};
```

这里的地址和容量必须与具体芯片手册一致。`FLASH` 和 `RAM` 是逻辑名称，后续区域通过 `PL_REF(FLASH)` 与 `PL_REF(RAM)` 引用它们。

添加初始化区域：

```c
const pl_link_region_t pl_regions[] = {
    {
        .name = "app_init",
        .type = PL_LINK_INIT,
        .memory = PL_REF(FLASH),
        .load_memory = PL_REF(FLASH),
        .address = PL_AUTO,
        .size = PL_LINKER_SIZE,
        .alignment = 4,
        .start_symbol = PL_SYMBOL(pl_app_init_start),
        .end_symbol = PL_SYMBOL(pl_app_init_end),
        .load_symbol = PL_NO_SYMBOL,
    },
};
```

`PL_LINKER_SIZE` 表示表项数在链接前未知。链接器收集实际函数指针后，`pl_app_init_end - pl_app_init_start` 就是实际表大小。

## 3. 生成链接器输入

从项目根目录运行 GNU 后端：

```powershell
python tools/generate_linker.py example/layout.pl.c --toolchain gnu --linker-out build/pl_sections.ld --header-out build/generated/pl_linker_symbols.h
```

应看到：

```text
generated build/pl_sections.ld
generated build/generated/pl_linker_symbols.h
```

生成的头文件必须位于 C 编译器 include 路径中。将 `build/generated` 加入 `-I` 路径。

## 4. 注册初始化函数

在任意 `.c` 文件中：

```c
#include "pl_linker.h"

static void clock_init(void)
{
}

PL_INIT(app_init, 010, clock_init);
```

`app_init` 必须和布局区域 `.name = "app_init"` 一致。`010` 是优先级；在同一组中数值较小的条目先被遍历。

## 5. 在启动流程中遍历

在启动代码或项目初始化入口中：

```c
#include "pl_linker_symbols.h"

void run_app_initializers(void)
{
    const pl_init_entry_t *entry;

    for (entry = pl_app_init_start; entry < pl_app_init_end; ++entry) {
        entry->function();
    }
}
```

空表是安全的：此时起点等于终点，循环不会执行。

## 6. 链接 GNU Arm 工程

先把生成脚本作为原始芯片 `.ld` 的扩展引入。当前 demo 的 `pl_sections.ld` 包含 `MEMORY`，因此实际工程应避免与已有 `MEMORY` 块重复定义。推荐做法是把生成器后续扩展为 fragment 模式，或由布局文件成为唯一内存描述。

示例验证命令：

```powershell
arm-none-eabi-ld -T build/pl_sections.ld build/main_arm.o -o build/demo.elf
```

真实工程通常通过构建系统传入 `-T`，并保留芯片启动、向量表与默认 section 的原始脚本规则。详见 [05-构建与工具链](05-构建与工具链.md)。

## 7. 加入 RAM 函数

在 `pl_regions[]` 中增加：

```c
{
    .name = "fast_code",
    .type = PL_LINK_RAM_CODE,
    .memory = PL_REF(RAM),
    .load_memory = PL_REF(FLASH),
    .address = PL_AUTO,
    .size = PL_LINKER_SIZE,
    .alignment = 4,
    .start_symbol = PL_SYMBOL(pl_fast_code_start),
    .end_symbol = PL_SYMBOL(pl_fast_code_end),
    .load_symbol = PL_SYMBOL(pl_fast_code_load_start),
},
```

给函数添加属性：

```c
PL_RAMFUNC(fast_code)
void motor_control_step(void)
{
}
```

启动阶段在第一次调用函数前复制：

```c
void copy_fast_code(void)
{
    uint8_t *destination = pl_fast_code_start;
    const uint8_t *source = pl_fast_code_load_start;

    while (destination < pl_fast_code_end) {
        *destination++ = *source++;
    }
}
```

完整代码见 [example/main.c](../example/main.c)。
