# 布局描述语言

布局文件是一个普通 C 源文件，建议命名为 `board_layout.pl.c`。生成器只关心其中两个全局数组：

```c
const pl_memory_t board_memories[] = { ... };
const pl_link_region_t board_regions[] = { ... };
```

数组变量名可以改变；元素类型必须是 `pl_memory_t` 或 `pl_link_region_t`。建议使用指定初始化器，字段含义更清晰，也符合当前解析器的主要测试路径。

## `pl_memory_t`

定义于 [inc/pl_linker_layout.h](../inc/pl_linker_layout.h)：

```c
typedef struct {
    const char *name;
    uint64_t origin;
    uint64_t size;
    pl_memory_attributes_t attributes;
} pl_memory_t;
```

| 字段 | 作用 | 规则 |
| --- | --- | --- |
| `name` | 内存区逻辑名称 | 必须是唯一 C 标识符形式，如 `FLASH`、`RAM_D2`。 |
| `origin` | 起始地址 | 支持十进制、十六进制和受支持数值表达式。 |
| `size` | 总容量 | 必须大于 0。推荐 `PL_KIB()` / `PL_MIB()`。 |
| `attributes` | 访问属性 | `PL_MEMORY_RX`、`PL_MEMORY_RW` 或 `PL_MEMORY_RWX`。 |

生成器按地址排序检查内存范围重叠：

$$
[origin_A, origin_A + size_A) \cap [origin_B, origin_B + size_B) = \varnothing
$$

## `pl_link_region_t`

```c
typedef struct {
    const char *name;
    pl_link_kind_t type;
    const char *memory;
    const char *load_memory;
    uint64_t address;
    uint64_t size;
    uint32_t alignment;
    const char *start_symbol;
    const char *end_symbol;
    const char *load_symbol;
} pl_link_region_t;
```

| 字段 | 作用 |
| --- | --- |
| `name` | 逻辑区域名，也是输入 section 命名的一部分。必须唯一。 |
| `type` | 区域行为：`PL_LINK_INIT`、`PL_LINK_RAM_CODE`、`PL_LINK_RESERVED`。 |
| `memory` | 运行内存，使用 `PL_REF(FLASH)` 形式。 |
| `load_memory` | 初始映像所在内存。没有时使用 `PL_NO_MEMORY`。 |
| `address` | 固定地址，或 `PL_AUTO`。 |
| `size` | 固定容量，或 `PL_LINKER_SIZE`。 |
| `alignment` | 起始地址对齐，必须为非零 2 的幂。 |
| `start_symbol` | 运行范围起始符号，使用 `PL_SYMBOL(name)`。 |
| `end_symbol` | 运行范围结束符号，使用 `PL_SYMBOL(name)`。 |
| `load_symbol` | 初始映像起点。没有时使用 `PL_NO_SYMBOL`。 |

### `PL_LINK_INIT`

收集：

```text
.pl.init.<name>.*
```

适用场景：函数初始化表、设备驱动注册表、协议处理器注册表。当前 GNU 后端为此模式生成 `KEEP` 与 `SORT_BY_NAME`。

推荐：

```c
.address = PL_AUTO,
.size = PL_LINKER_SIZE,
.memory = PL_REF(FLASH),
.load_memory = PL_REF(FLASH),
.load_symbol = PL_NO_SYMBOL,
```

### `PL_LINK_RAM_CODE`

收集：

```text
.pl.ram_code.<name>
```

必须提供 `.load_memory`。适合时间敏感函数、Flash 擦写期间仍需运行的函数，或需要从 RAM 取指的中断处理函数。

推荐：

```c
.memory = PL_REF(RAM),
.load_memory = PL_REF(FLASH),
.size = PL_LINKER_SIZE,
.load_symbol = PL_SYMBOL(my_region_load_start),
```

### `PL_LINK_RESERVED`

不收集任何输入 section，只占用固定内存范围。必须使用固定 `size`，不能使用 `PL_LINKER_SIZE`。

可用于：与 bootloader 约定的 RAM 通信区、DMA 描述符区、跨复位保留区地址规划。当前 demo 只负责地址保留，并不自动给变量分配到该区域。

## 辅助宏和表达式

| 写法 | Python 中的意义 | C 编译时的意义 |
| --- | --- | --- |
| `PL_KIB(128)` | 计算 `128 * 1024` | `uint64_t` 容量表达式。 |
| `PL_MIB(2)` | 计算 `2 * 1024 * 1024` | `uint64_t` 容量表达式。 |
| `PL_AUTO` | 特殊自动地址标记 | `UINT64_MAX`。 |
| `PL_LINKER_SIZE` | 大小由链接器结算 | `UINT64_MAX - 1`。 |
| `PL_REF(RAM)` | 内存引用 `RAM` | 字符串 `"RAM"`。 |
| `PL_SYMBOL(foo)` | 符号名 `foo` | 字符串 `"foo"`。 |
| `PL_NO_MEMORY` | 没有加载内存 | 空指针。 |
| `PL_NO_SYMBOL` | 没有加载符号 | 空指针。 |

Python 不读取宏展开后的数值；它识别这些宏调用的 token 形式。因此布局文件内应保持这些宏名称，不要用另一层自定义宏包裹它们。

## 地址策略

`PL_AUTO` 的当前实现是“把最终位置交给链接器按区域输出顺序决定”。这对大小为 `PL_LINKER_SIZE` 的区域是必要的，因为 Python 在链接前不知道实际输入 section 的长度。

固定地址适合硬件协议、bootloader 合同或明确保留的地址范围。选择固定地址时必须自己保证它不和启动脚本中的 `.data`、堆、栈或其他 RAM 区域冲突。当前生成器检查内存区重叠，但不解析外部原始链接脚本，因此无法知道那些区域。
